RAG-Powered Financial Filing Analyst

A Retrieval-Augmented Generation system that answers complex financial questions over SEC 10-K filings with numerical reasoning, source citations, and hallucination detection.

Architecture & Approach

The system ingests SEC 10-K filings from EDGAR, parsing them into structured sections (Risk Factors, MD&A, Business Description, Financial Statements). Documents are chunked using three strategies — recursive character splitting, semantic chunking based on embedding similarity, and section-aware chunking that respects document structure. Chunks are embedded and indexed in ChromaDB.

The retrieval layer implements an ensemble strategy combining dense vector search, BM25 sparse retrieval, and Maximum Marginal Relevance (MMR) for diversity. Multi-query expansion generates alternative query phrasings to improve recall. A contextual compression layer reranks retrieved chunks by relevance.

A financial knowledge graph (NetworkX) extracts entities (companies, metrics, dates, monetary amounts) and relationships from the filings, augmenting retrieval with graph traversal for relationship-aware context. The generation layer uses chain-of-thought prompting optimized for financial numerical reasoning with mandatory source citations.

Guardrails & Evaluation

A multi-layer guardrail pipeline validates every response: factual consistency checking (sentence-level grounding verification), hallucination detection (cross-referencing generated claims against retrieved context), numerical validation (extracted numbers compared against source with configurable tolerance), and format compliance. The evaluation framework measures Precision@K, Recall@K, MRR, NDCG for retrieval, and faithfulness, answer relevancy, and numerical accuracy for generation.

Real-Time Streaming Fraud Detection

An end-to-end streaming fraud detection pipeline processing millions of transaction events through Kafka, Spark Structured Streaming, and ensemble ML scoring with sub-second latency.

System Architecture

The pipeline follows an event-driven architecture: a transaction data simulator generates realistic financial events with configurable fraud patterns (card testing via rapid small amounts, account takeover via unusual locations, velocity abuse, and merchant collusion). Events are published to Apache Kafka topics with exactly-once semantics.

Spark Structured Streaming consumes events with watermark-based processing, computing real-time features across multiple sliding windows (1-minute, 5-minute, 15-minute, 1-hour, 24-hour). Features include transaction velocity, cumulative amounts, geographic velocity (distance/time between consecutive transactions), merchant risk scoring, behavioral deviation from historical patterns, cyclical time encoding, and device-level aggregations — 48 features total.

ML Scoring & Alerting

An ensemble of CatBoost, LightGBM, and XGBoost classifiers scores each transaction in real-time. Models are trained with cost-sensitive learning (asymmetric misclassification costs), calibrated via Platt scaling, and served through a scorer that applies three-tier thresholding: block (immediate decline), review (queue for analyst), or allow. Alerts are priority-scored by combining model confidence, transaction amount, and customer value, then routed to a Kafka output topic.

Observability

Full observability via Prometheus metrics (13 metrics covering throughput, latency histograms, fraud rates, consumer lag) and Grafana dashboards with 8 panels. A Streamlit dashboard provides real-time monitoring with alert timelines, severity distributions, and geographic heatmaps. The entire system is orchestrated with Docker Compose (6 services: Zookeeper, Kafka, Kafka UI, Prometheus, Grafana, Application).

Credit Risk Modeling with Responsible AI

Production-grade credit scoring pipeline with multi-table feature engineering across 7 relational tables, causal inference, fairness audits, and full model explainability for 307K loan applications.

Multi-Table Feature Engineering

The core challenge is extracting predictive features from 7 relational tables in the Home Credit dataset (307K applications). The pipeline computes hundreds of features across domains: bureau features (active loan counts, total debt, credit/debt ratios, past-due history), bureau balance aggregations, previous application features (approval rates, amount granted vs. applied), installment payment behavior (payment ratios, days before/after due, consistency), credit card utilization trends, and POS cash contract features. Application-level features include income ratios, external source score combinations, and document flag aggregations.

Model Comparison & Cost-Sensitive Learning

Five model architectures are compared: Logistic Regression (baseline), XGBoost with scale_pos_weight, LightGBM with focal loss, CatBoost with class weights, and a PyTorch neural network with batch normalization, dropout, and calibrated sigmoid output using custom focal loss. Hyperparameter optimization is performed with Optuna (Bayesian TPE search), and all experiments are tracked in MLflow.

Causal Inference

Goes beyond correlation-based modeling by applying DoWhy for causal graph specification, identification, and estimation (propensity score matching, IPW, doubly robust). EconML causal forests estimate heterogeneous treatment effects (CATE) across borrower subgroups. Refutation tests (placebo treatment, random common cause, subset validation) validate causal claims.

Fairness & Explainability

Comprehensive fairness audit: demographic parity, equal opportunity, equalized odds, and disparate impact ratio across protected groups with bias mitigation via threshold adjustment and reweighting. SHAP provides both global and local explainability with regulatory-compliant documentation. Evaluation includes AUC-ROC, Gini, KS statistic, calibration analysis, and decile-level rank ordering.

MLOps Platform with Drift Detection

Complete MLOps lifecycle — train, deploy, monitor, detect drift, auto-retrain — using NYC Taxi data with natural COVID-era distribution shift as the proving ground.

End-to-End MLOps Lifecycle

The platform implements every stage of production ML: a Feast feature store manages feature definitions, materialization, and online/offline serving to ensure training-serving consistency. MLflow tracks experiments (parameters, metrics, artifacts) and manages the model registry with stage transitions (Staging → Production). Model serving is handled by a FastAPI application with Pydantic validation, Prometheus metrics, and health endpoints.

Drift Detection Engine

The custom drift detector implements multiple statistical methods: Population Stability Index (PSI) for overall distribution shift, Characteristic Stability Index (CSI) per feature, Kolmogorov-Smirnov tests, Wasserstein distance, ADWIN (Adaptive Windowing) for streaming drift, and Page-Hinkley tests. Each method has configurable warning and critical thresholds.

The NYC Taxi dataset provides the perfect testbed because COVID-19 caused massive natural distribution shift starting March 2020 — trip volumes collapsed, geographic patterns changed, and fare distributions shifted. Training on pre-2020 data and monitoring through 2020-2022 demonstrates real-world drift detection and its consequences.

Auto-Retraining & Data Quality

When drift exceeds critical thresholds, the auto-retraining pipeline triggers: fetches latest data, retrains with the same hyperparameters, compares new model against production (champion/challenger), and auto-promotes if performance improves. A rollback mechanism protects against degradation. Data quality validation checks schema, statistical ranges, completeness, and distributional properties before any training or serving.

AML Transaction Monitoring with LLM Alert Triage

A two-layer anti-money laundering system combining rule-based monitoring, ML-powered suspicious activity detection, graph-based network analysis, and LLM-powered alert triage for compliance automation.

Hybrid Detection Architecture

The system processes transactions from the IBM AML dataset (up to 180M transactions) through two detection layers. Layer 1 is a rule engine implementing classic AML typologies: structuring detection (transactions clustered just below reporting thresholds), rapid movement of funds (large inflows immediately followed by outflows), round-tripping (circular fund flows through chains of accounts), and velocity-based rules. Each rule produces a risk score and rule identifier.

Layer 2 applies ML classification (LightGBM/XGBoost with cost-sensitive learning) on engineered features combining transaction-level, account-level, behavioral, network, and temporal dimensions. The extreme class imbalance (0.1-0.3% positive rate) is handled through SMOTE, ADASYN, and threshold optimization targeting specific recall levels.

Graph-Based Network Analysis

A NetworkX transaction graph models money flows between entities. The graph analysis module performs community detection (Louvain algorithm) to identify clusters of related accounts, cycle detection to find circular money flows (a hallmark of layering), centrality analysis (PageRank, betweenness) to identify intermediary/hub accounts, and subgraph extraction for suspicious clusters. Graph features feed into the ML model, and graph visualizations support human investigation.

LLM-Powered Alert Triage

The key differentiator: for each generated alert, the system retrieves all contextual information (transaction history, graph relationships, triggered rules, prior alerts) and generates a structured case summary using an LLM (via LangChain). The summary includes a narrative description of suspicious activity, key risk indicators, event timeline, recommended disposition (Escalate to SAR, Continue Monitoring, or Close), and confidence level. Few-shot prompting ensures consistency, and output validation checks generated facts against source data. The compliance reporter can generate SAR draft narratives for regulatory filing.
